See where each coding session spends its tokens

Your agent sends its whole context again on every turn. llmly reads the logs that Copilot, Codex and Claude Code already keep, and shows which turns, tools and sub-agents made a session expensive.

uvx llmly

Needs uv. Opens in your browser in about a minute.

Copilot · Codex · Claude Code
macOS, Linux, Windows · local files only · no account

Why it exists

A long agent session gets expensive in a way the total hides. Each turn sends the conversation so far, so a session with 15 requests can carry a million input tokens. The cost lands where the context grew: a file read that pulled in 400 lines, a test run with long output, a sub-agent that started from scratch, or a compaction that threw the cache away.

The logs to see this are already on your disk. Copilot writes debug logs in VS Code's workspace storage, Codex writes rollout files, and Claude Code writes one transcript per session. llmly parses all three into one chart per session, and ties each tool call to the model request that read its result.

Read a chart

Every session is one card. All cards share the y-axis, so the heaviest session fills the frame and the rest compare against it.

  1. Start and totals. When the session started, its total input, and the uncached part of it in red. Uncached input is what you pay full price for.
  2. Source and detail. Copilot, Codex or Claude, then output, cache-hit rate, cost, requests, sub-agents and compactions.
  3. Shared scale. One y-axis for every card in the result, so a flat card next to a steep one means what it looks like.
  4. Cumulative input. The solid blue line is the main agent. Each dot is one model request. Dot size is that request's input.
  5. User message. A star marks each prompt you typed.
  6. Sub-agent. A dashed line starts where a sub-agent was spawned. Its tokens count toward the session.
  7. Compaction. An orange diamond. The next request starts from a summary, so the context shrinks and the cache starts cold.
  8. Cache hit. Blue is 70% or more of the input from cache, amber is 30–70%, red is under 30%.
  9. Per-turn input. The lower band is each request's own input. The drop after the diamond is the compaction.
  10. First prompt. The card's title is the first thing you asked for.

Tour

Six views, all from the same logs. Every control writes to the URL, so a refresh or a shared link opens the same view.

Sessions grid

The default view: the top 50 sessions of the last 24 hours, heaviest first.

  • Pick a window with the date fields, the ◀ ▶ steps, or 1h to 90d.
  • Filter to one source: all, Copilot, Codex or Claude.
  • Sort by total input, cost, most recent, uncached, requests or duration.
  • Set a top-N cap and a minimum token count to drop small sessions.
  • Show sub-agents inside their parent, or as their own lines.

Session detail: turns

Click a card to open it. One row per model request, grouped by agent.

  • Model, reasoning level, input, cached, uncached, output and cost for each request.
  • The tool calls that ran before each request, so you see what it read.
  • Hover a dot to find its row, or a row to find its dot.
  • Expand a row for each tool's arguments and result.

By tool

The same session, rolled up by tool name.

  • Calls, failures, new input, uncached input, output and cost per tool.
  • New input is how much a request's context grew since the one before. It points at the tool whose output was large.
  • A tab per tool lists each call with its arguments.
  • The file-read tab switches between a table and a heat map of the lines read.

By file

Tool calls grouped by the file path in their arguments.

  • See which files the agent read and edited, and how often.
  • Filter by a path, such as /docs, to check one area.

Table

One row per session, for a week or more at a time.

  • Model, reasoning level, requests, sub-agents, input, cached, cache %, output, cost and duration.
  • Click a column header to sort. Click a row for its detail.

Calendar

A year of daily use. Click a day to show only that day.

  • Copilot alone shows billed credits (AIC) or dollars.
  • Codex, Claude and mixed views show input tokens, or estimated dollars where model prices are known.

Is it for you?

Worth it if

  • You use Copilot agent mode, Codex or Claude Code and want to know why one session cost more than another.
  • You want to find the tool calls or sub-agents that grow the context.
  • You want to compare cache hits across models and sources.

Skip it if

  • You need billing totals for a team. llmly reads one machine's logs.
  • You need exact cost for Codex or Claude. Their logs have no billed amount, so llmly shows tokens or an estimate from list prices.
  • You use another agent. Only these three sources are parsed today.

llmly only reads files. It sends nothing anywhere, and the server listens on 127.0.0.1 unless you pass --host.

Start

  1. Run it about 1 minute

    Needs uv. The first run installs Flask; later runs start at once. It opens on port 5057, or the next free port.

    uvx llmly

  2. Run from source about 2 minutes

    git clone https://github.com/byronwall/llmly.git cd llmly uv run app.py

  3. No Copilot sessions? a few minutes

    Print every folder llmly checked and how many logs it found. Then pass the right one with --copilot-storage.

    uvx llmly --diagnose-logs

What the numbers mean

Input
The full prompt of a request, cached part included. For Claude this is input_tokens + cache_read + cache_creation.
Uncached
Input minus cached. The part sent at full price.
AIC
Copilot's billed credits, from the per-request value in its log. 100 AIC is $1.
Reasoning
The effort level the request asked for (low to xhigh), not a token count.
Compaction
A request that summarized the conversation to free context.

For coding agents

The viewer is a JSON API with a page on top. With llmly running, an agent can read the same data with curl:

RouteReturns
GET /api/sessionsSession summaries. Query: source (all, copilot, codex, claude), start_ts and end_ts or since_hours, sort, limit, min_tokens.
GET /api/session/<source:id>One session: every request and the tool calls before it.
GET /api/daily_usageDaily totals. Query: source, unit (aic or usd).
GET /api/statsTotals for the last N hours: sessions, requests, input, cached, output. Query: since_hours, source.
curl -s 'http://127.0.0.1:5057/api/sessions?source=claude&since_hours=24&sort=uncached&limit=5'

How I built it

llmly started in June 2026 as a Flask app I ran from a checkout. Copilot came first, then Codex, then Claude Code. Each source logs usage its own way. Copilot reports billed credits for each request. Codex writes a token count event after each turn. Claude splits one request across several transcript lines that repeat the same usage, so the parser keeps one per request ID. All three end up as the same session shape, and the browser draws the charts as SVG from that JSON.

The command I wanted was uvx llmly. Getting there meant making llmly/ the package, with its templates and JavaScript inside the wheel, and a console script that picks a free port and opens the browser. I wrote up the packaging in Packaging llmly for PyPI. The publish script checks the package name before it uploads. That check already stopped one upload after a merge put the old name back.

25 commits · 2,954 lines of Python · 2,505 lines of JavaScript modules · 17 tests on temporary log fixtures · no build step

The demo on this page is the real frontend. A build script writes made-up logs for all three sources, runs llmly's own parsers on them, and saves the API answers as JSON. A small script in the page answers the viewer's requests from those files.
